# OneDrive 做题记录同步说明与验收

## 解决的问题

网页放在 OneDrive 中，只能让源码和题库文件跟着同步。做题记录保存在浏览器的 IndexedDB 中，失败时会降级到其他浏览器存储；它们不会随网页文件复制到另一台电脑。

例如，在电脑 A 完成一篇阅读后，电脑 B 虽然能打开同一份网页，仍然看不到这次做题记录。本功能让网页在用户授权后，把记录写到 OneDrive 文件夹，另一台电脑再读取和合并这些文件。

## 使用方式

1. 先在有旧记录的电脑上，用原来的浏览器和网页地址打开项目，通过“导出数据”保存备份。
2. 在“设置 → 数据管理”中点击“连接 OneDrive 文件夹”，选择 OneDrive 内固定的父文件夹，例如项目目录。
3. 网页自动创建 `IELTS-Record-Sync` 子目录。等待 OneDrive 客户端完成上传。
4. 在另一台电脑使用支持文件夹选择的桌面浏览器，选择对应的同一个父文件夹。不要选择自动生成的子目录。
5. 换电脑前点击“立即同步 / 重新授权”，并确认 OneDrive 客户端完成上传。每台电脑都需要单独授权。

## 具体改动

| 改动 | 用户可以感受到的变化 |
| --- | --- |
| 增加文件夹连接、立即同步、断开和恢复副本下载按钮 | 可以在设置中操作和查看状态 |
| 每个浏览器连接写一个独立文件 | 两台电脑不用争着覆盖同一个文件 |
| 按记录 ID 合并，保留完整记录字段 | 已有记录和答案可以合并，同一 ID 不重复计数 |
| 保存递增版本和删除标记 | 修改和删除会传播，未修改的旧副本不会把已删除记录带回来 |
| 同一条记录并发修改时选择一个确定版本 | 各端最终一致；不会逐字段拼接两次修改，也不保证选择现实时间最后一次编辑 |
| 相关记录变动约 1.5 秒后同步，页面可见时每 15 秒检查，重新聚焦也检查 | 授权有效且页面打开时自动更新；无变化不重复写文件 |
| 首次远端合并前保留本连接的本机恢复副本 | 可以下载同步前记录；更换或断开连接前应先下载需要保留的副本 |
| 损坏文件停止本轮同步；权限失效提示重新授权；写入失败可重试 | 异常时保留本机记录，并说明原因 |
| 忽略项目根目录下的 `IELTS-Record-Sync` | 选择项目目录同步时，生成的个人记录不会被 Git 默认跟踪 |

文件格式为 `ielts-record-sync-v1`，设备文件名为 `records-<随机ID>.json`。同一 ID 通过逻辑计数器、设备 ID 等稳定顺序决定冲突结果，不依赖电脑时钟。合并通过现有仓储事务队列写入记录。

## 范围和边界

- 只同步做题记录及答案等附属字段。主题、题库设置、词汇库和独立成就数据仍由原有逻辑管理。
- 网页只读写用户授权的本机目录，不登录 Microsoft 账号，也不调用 OneDrive 云端接口。网页显示本机读写成功，不代表云端上传或另一台电脑下载完成。
- 关闭网页后，网页不再读写记录文件；已写出的文件继续由 OneDrive 客户端传输。
- 连接句柄、合并基线和恢复副本保存在独立的浏览器 IndexedDB 中。不支持文件夹选择时仍可使用原有导出/导入功能。
- 不要手动清理设备文件或删除标记，否则可能重新引入旧记录。文件是明文 JSON，目录访问和分享权限由用户管理。
- 浏览器文件选择需要用户操作及相应权限；保存句柄后仍需检查权限。参见 [Chrome 官方 File System Access 说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

```sh
node developer/tests/js/practiceRecordPersistence.test.js
node developer/tests/js/practiceCoreAppStateSync.test.js
node --check js/utils/oneDriveRecordSync.js
git diff --check
```

新增同步测试为 13 项，覆盖旧记录和答案合并、双端新增、去重、修改、删除传播、并发冲突、损坏文件、权限失效、写入失败重试、恢复副本、同步期间新增和重启后离线删除。另两项现有回归检查通过。新增测试无需安装依赖。
